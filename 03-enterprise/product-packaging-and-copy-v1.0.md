# 星球发行·企业版：产品包装与对外文案基线 v1.0

> 日期：2026-09-11  
> 状态：正式产品表达基线

## 1. 产品定义

星球发行企业版帮助发行商、唱片公司、版权公司和音乐平台，用自己的品牌快速搭建音乐发行系统，或通过 API 将音乐发行能力接入现有产品。

对外产品结构保持简单，只保留两个核心入口：

1. **自有品牌发行系统**：适合没有完整发行系统，或希望以自己的品牌对外经营发行业务的企业。
2. **发行 API**：适合已经有网站、App 或内部业务系统，只需要接入音乐发行能力的企业。

现有发行底层能力继续复用，不在企业版产品包装中重新定义一套发行引擎。

## 2. 客户理解路径

企业官网和销售材料优先回答四个问题：

1. 这是什么？
2. 适合谁？
3. 能解决什么问题？
4. 多少钱？

技术架构、协议和系统内部名词全部放在第二层。

推荐的第一层理解方式：

```text
没有发行系统
→ 直接搭一套自有品牌发行系统

已经有网站 / App / 内部系统
→ 通过发行 API 接入发行能力
```

## 3. 平台版本与价格

| 版本 | 年费 | 主要客户阶段 | 核心定位 |
| --- | ---: | --- | --- |
| 基础版 | ¥19,800 / 年 | 刚开始做发行业务 | 用较低门槛建立一套完整可运行的发行系统 |
| 专业版 | ¥59,800 / 年 | 已有稳定客户和曲库 | 正式长期经营发行业务的主销版本 |
| 企业版 | ¥129,800 / 年起 | 大规模或复杂系统接入 | 大曲库、高级接入、API 和专属服务 |

三个版本统一收取发行使用费：

**¥1 / 首 / 渠道**

一首歌曲发行到一个目标音乐平台，计一次发行使用量。

### 3.1 基础版

适合刚开始做发行业务的小型发行团队、厂牌和版权公司。

核心范围：
- 1 万首曲库
- 20 个合作客户
- 企业品牌与客户发行门户
- 客户提交、审核、发行完整流程
- 国内外音乐平台发行
- 数据与收入报表
- Excel 批量导入

### 3.2 专业版

适合已有稳定客户和曲库、长期经营发行业务的团队。

核心范围：
- 10 万首曲库
- 100 个合作客户
- 独立域名
- 完整自有品牌体验
- 多客户收入分账
- 批量数据和系统对接
- SFTP / XML
- 优先支持

专业版作为默认主销版本。

### 3.3 企业版

适合大型发行商、平台企业以及复杂技术接入项目。

核心范围：
- 30 万首曲库起
- 客户规模按项目确认
- 发行 API 包含
- DDEX 等高级接入方式
- 大型历史曲库迁移
- 专属客户经理
- 专属技术支持 / SLA

企业版采用“起价”而不是完全标准化固定报价，最终价格根据曲库、数据迁移、系统对接和服务范围确认。

## 4. 独立发行 API

已有网站、App 或内部系统，只需要发行能力的企业，可单独购买发行 API。

价格基线：

**¥9,800 / 年起 + ¥1 / 首 / 渠道**

独立 API 方案不包含完整企业发行后台和客户发行门户。

API 对外按业务能力描述：
- 音乐内容
- 提交发行
- 平台状态
- 数据与报表
- 收入与结算

具体资源模型、凭证、Webhook、日志、错误处理和协议细节进入 API 文档说明。

## 6. 官网信息架构

一级导航：

```text
产品
解决方案
价格
发行 API
申请企业版
```

`API 文档` 不作为一级商业导航，在发行 API 页面、页脚和相关 CTA 中进入。

### 首页

先回答：企业版是什么、两种使用方式、能完成哪些发行业务、适合什么企业、价格如何。

### Product

不先讲三层技术架构，先讲真实业务流程：

```text
客户提交音乐
→ 团队审核
→ 正式发行
→ 查看上线进度
→ 数据与结算
```

随后再解释客户门户、企业后台和发行服务三部分如何协作。

### Solutions

不先要求客户判断自己属于哪类企业，先从业务问题进入：

- 想做自己的发行平台
- 已经有大量曲库
- 已经有网站或 App
- 已经有内部系统

再映射到发行商、唱片 / 版权公司、AI 音乐平台和音乐科技平台等典型客户类型。

### Pricing

页面第一层先说明：
- 基础版：刚开始做发行
- 专业版：稳定经营发行业务
- 企业版：大规模或复杂业务

具体功能差异放在对比表第二层。

## 7. 对外表达原则

1. 能说客户要完成的事情，就不要先说系统模块。
2. 能用中文业务语言，就不要优先使用英文专业名词。
3. 标题先给结论，正文再解释范围。
4. 不用行业知识作为理解前提。
5. 技术人员需要的信息进入 API 文档，不挤占商业首页。
6. 不新增当前产品范围之外的能力承诺。
7. 首页、销售材料、报价单和申请页使用同一套产品名称与价格口径。
